+# 部署检查清单（AI 助手上线）
+
+适用版本：feature/ai-model 分支（含 `/api/v1/ai/chat`、`/api/v1/ai/draft-post`、`/api/v1/ai/search-advice`）。
+部署形态：Docker Compose（db + backend + frontend/nginx）。
+
+## 一、上线前必填环境变量（根目录 .env）
+
+| 变量 | 必填 | 说明 |
+|---|---|---|
+| `JWT_SECRET` | ✅ 必填 | 至少 32 字符随机串，签发登录令牌 |
+| `ADMIN_PASSWORD` | ✅ 必填 | 管理员 admin 的初始密码 |
+| `MODEL_BASE_URL` | ✅ 开模型必填 | OpenAI 兼容网关地址，填到 `/v1`（如 `https://aiapi.usst.edu.cn/v1`） |
+| `MODEL_NAME` | ✅ 开模型必填 | 模型名，必须在网关白名单内（用 `GET {BASE_URL}/models` 核对，当前为 `DeepSeek-V4-Flash`） |
+| `MODEL_API_KEY` | ✅ 开模型必填 | 网关密钥，只写在根 .env，不进代码/镜像/日志 |
+| `MODEL_DISABLED` | ✅ 开模型必填 | 设为 `false`；留空或 `true` 则模型关闭，走规则降级 |
+| `MODEL_TIMEOUT_SECONDS` | 建议 | 默认 10（与交接文档及测试基线一致），不要设 5 |
+| `CORS_ORIGINS` | 直连后端时必填 | JSON 数组，填前端真实访问源（走 nginx 同源转发时不触发 CORS，可留默认） |
+
+说明：
+- Compose 的 `${VAR:-默认}` 从根目录 `.env` 读取；未填的 MODEL_* 默认空 + `MODEL_DISABLED=true`，后端自动走规则降级，不会启动失败。
+- 密钥只存在于后端容器环境变量；前端镜像与代码不接触任何密钥。
+- 可用 `python scripts/configure_local.py` 生成根 `.env` 骨架（保留已有配置、不打印凭据），再补 MODEL_* 三项。
+
+## 二、启动顺序
+
+```bash
+# 1. 准备根目录 .env（上表变量）
+# 2. 一键启动（db 健康检查通过后 backend 自动迁移+seed，再起 frontend）
+docker compose up --build -d
+# 3. 查看状态
+docker compose ps
+docker compose logs -f backend
+```
+
+容器内自动执行：`alembic upgrade head && python seed.py && uvicorn app.main:app --host 0.0.0.0 --port 8000`。
+前端容器：多阶段构建（node 构建 dist → nginx 托管），`/api/*` 由 nginx 转发到 `backend:8000`，对外端口 `5173:80`。
+
+## 三、健康检查
+
+| 检查项 | 命令/地址 | 预期 |
+|---|---|---|
+| 后端存活 | `curl http://<主机>:8000/docs` | 200 |
+| 数据库就绪 | `docker compose ps` 中 db 为 healthy | healthy |
+| 迁移已执行 | `docker compose exec backend alembic current` | 显示最新版本（20261023_content） |
+| 前端就绪 | 浏览器打开 `http://<主机>:5173` | 登录页正常渲染 |
+| 代理转发 | `curl http://<主机>:5173/api/v1/layers`（带 token） | 返回业务 JSON 而非 404/502 |
+
+## 四、验证 AI 助手生效
+
+1. 登录任意账号（或注册学生账号）。
+2. 打开「AI 助手」页，输入物品描述（例：`今天下午在图书馆3楼丢了一把蓝色折叠伞`）并发送。
+3. 预期：聊天区返回整理回复；下方「整理结果」卡片出现字段，右上角标签显示 **实时模型**；出现「已帮你预填」提示。
+4. 点「应用到发布」→ 发布页空字段被预填（已手写内容不被覆盖）→ 提交成功。
+5. 命令行等价验证（不经过浏览器）：
+
+```bash
+TOKEN=$(curl -s -X POST http://<主机>:5173/api/v1/auth/login \
+  -H "Content-Type: application/json" \
+  -d '{"username":"<账号>","password":"<密码>"}' | python -c "import sys,json;print(json.load(sys.stdin)['token'])")
+curl -s -X POST http://<主机>:5173/api/v1/ai/chat \
+  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
+  -d '{"message":"今天下午在图书馆3楼丢了一把蓝色折叠伞"}'
+# 预期：source 为 "model"、degraded 为 false、form_patch 含字段、actions 为 ["prefill_form"]
+```
+
+## 五、模型不可用时的降级预期（设计行为，非故障）
+
+- 触发条件：网关超时/403/5xx、密钥失效、输出无法解析、`MODEL_DISABLED=true`。
+- 表现：
+  - 接口**不报错**，HTTP 200；
+  - `source` 变为 `rule`、`degraded` 变为 `true`；
+  - chat 含物品特征时仍返回规则整理的 `form_patch`（类别/建筑/楼层由关键词与建筑名匹配），纯闲聊返回固定引导语；
+  - 前端「整理结果」标签显示「规则整理」。
+- 业务红线保持：手动发布、筛选、认领、归还主流程不受模型影响；AI 不批准认领、不确认归还。
+
+## 六、安全红线核对
+
+- [ ] API Key 只在根 `.env` / 后端容器环境变量，未出现在前端代码、镜像层、日志、截图
+- [ ] `backend/.env`、根 `.env` 均被 `.gitignore`/`.dockerignore` 排除
+- [ ] 发给模型的内容经脱敏（手机号/邮箱/证件号替换为 `[已脱敏]`），不含精确位置、联系方式、认领证据
+- [ ] 生产 `CORS_ORIGINS` 不含 localhost（走 nginx 同源代理时除外）
