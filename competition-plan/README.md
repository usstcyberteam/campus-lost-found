# 校园寻物局｜参赛规划与码道提示词包

版本：v1.1 · 整理日期：2026-10-03

**交付范围：项目规划文档、码道阶段提示词和空白记录模板。本文档包不包含项目实现、模型测试或码道开发成果。**

需求来源改为场景分析与待验证假设，产品能力通过团队角色模拟、流程回归和匹配对照检查。外部人员参与不作为阶段通过条件；团队模拟不能证明真实需求强度、校方认可或实际找回率。

## 从哪里开始

1. 团队先阅读[项目分析报告](项目分析报告.md)，确认产品范围、角色、预算和分工。
2. 在码道新会话中先粘贴[统一上下文提示词](prompts/00-统一上下文.md)。
3. 按顺序使用阶段提示词，并提供该阶段所需输入。阶段 1、2 先做规格与设计，阶段 3 起的提示词供团队日后开发使用。
4. 对照[评分与验收清单](评分与验收清单.md)验收。阶段未通过时先修复，不自动进入下一阶段。
5. 使用[记录模板](记录模板.md)保存需求假设和实际记录。没有发生的开发或测试标记未执行，不补造。

## 配套资料

- [码道 Rules 与验收 Skill 设计](规则与验收技能设计.md)：供团队阶段 2 在码道中配置；当前未安装或启用。
- [评分与验收清单](评分与验收清单.md)：官方分值、内部目标、阶段和材料检查。
- [记录模板](记录模板.md)：场景与需求假设、开发证据、团队角色模拟和对照评估记录。

## 使用边界

后续开发以华为云码道为核心工具；其他工具生成的规划或草稿须说明来源，不能当作码道开发记录。本包是供团队使用的规划资料，不是提交时可直接宣称已完成的成果。

置信度：中。官方规则有已核实来源，产品效果、资源可用性及获奖竞争力仍需实际验证。
