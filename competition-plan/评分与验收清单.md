## 3. 按阶段验收

### 阶段 1–2：规格与设计

- [ ] 必做/暂缓范围确定，三人责任明确。
- [ ] 四类典型场景完整，需求假设与已知事实分开。
- [ ] 假设有设计依据、对应功能、验证方式和剩余不确定性。
- [ ] 公开与私密字段、角色权限、状态变化明确。
- [ ] 规格、数据、接口、验收不存在冲突。
- [ ] 码道 Rules 和验收 Skill 设计有实际用途。
- [ ] 码道和模型账号、额度及接口可用性记录清楚。

### 阶段 3：业务闭环

- [ ] 学生发布寻物和拾获，另一账号可浏览和申请。
- [ ] 未核验不能归还，学生不能执行工作人员操作。
- [ ] 核验拒绝后相关记录恢复可处理状态。
- [ ] 同一物品多个申请不造成多次归还。
- [ ] 重复归还请求得到一致结果，不重复发放协助记录。
- [ ] 私密特征、联系方式和认领证据不出现在公共接口。

### 阶段 4：地图

- [ ] 三个图层可切换，地图和大厅指向同一记录。
- [ ] 标点、室外范围和分层路线可保存与恢复。
- [ ] 缩放、刷新、图层切换后位置一致。
- [ ] 未标定比例尺不显示米数。
- [ ] 路线默认私密，手机操作可用。

### 阶段 5：匹配

- [ ] 无法判断的特征留空，用户确认后参与匹配。
- [ ] 候选最多三个，解释一致、冲突和缺失。
- [ ] 排序分数不称为找回概率。
- [ ] 模型、缓存、规则来源明确。
- [ ] 模型故障不阻断手动操作。
- [ ] 密钥只存后端，调用有限额，物品信息发送获得明确确认。

### 阶段 6：工单

- [ ] 学生只能为自己的记录申请协助。
- [ ] 未授权、未分配工作人员不能直接请求私密路线。
- [ ] 学生不能读取工作人员模拟点位。
- [ ] 模拟点位明确标记，未宣称实际覆盖或视频权限。
- [ ] 工单处理、结果反馈和徽章可追溯，重复操作不重复发放。

### 阶段 7：测试

- [ ] 权限检查包含直接接口调用，不仅检查页面按钮。
- [ ] 无图片、未知时间、同款物品、模糊描述和无候选均有处理。
- [ ] 连续 10 次完整流程无阻断问题，记录失败和修复。
- [ ] 按物品身份分组，验证集与测试集分开。
- [ ] 基线和推荐使用相同候选库、输入与筛选，图片信息使用说明清楚。
- [ ] Top-3 和误推荐报告实际次数与分母，目标与结果分开。
- [ ] 团队分别使用学生与工作人员账号执行任务，保留步骤、耗时、错误及修复记录。
- [ ] 角色模拟明确标记为内部测试，未声称真实用户试用或需求已验证。
- [ ] 小样本和演示数据局限已说明。

### 阶段 8–9：交付与展示

- [ ] 干净环境启动通过，依赖与配置说明完整。
- [ ] 工程、视频、PPT、证据属于同一版本。
- [ ] 开发来源真实，六个码道案例有对应任务、修改、验证与提交。
- [ ] 没有无依据的效率提升、找回率或创新首创宣称。
- [ ] 3 分钟内视频和 5 分钟介绍已实际计时。
- [ ] 备用环境/录像、网络和模型异常方案已演练。

## 4. 提交清单

- [ ] 作品介绍 PPT/PDF：需求、流程、架构、亮点、验证、码道及落地。
- [ ] 演示视频或有效链接：建议不超过 3 分钟，完整流程。
- [ ] 码道证明：真实对话、修改、排错和验证证据。
- [ ] 作品说明文档：依赖、启动、运行、开源组件及码道总结。
- [ ] 作品展览馆地址有效；README 可附 GitCode 仓库地址。
- [ ] 按官网格式、命名、大小要求核对，相关文档单文件不超过 20MB。
- [ ] 决赛补齐完整源码、正式 PPT、稳定演示环境。
- [ ] 提交后核对状态，最终版本同时保持最佳稳定版本。

提交以[官方赛题页](https://developer.huaweicloud.com/competition/information/1300000338/circumstance)及组委会后续通知为准。

## 5. 判定方法

用“通过 / 不通过 / 未执行 / 不适用（附原因）”记录各项；只有实际验证通过才能勾选。业务、权限和真实性项失败时，不把自评分当作阶段通过依据。界面漂亮不能替代完成度或需求证据。
