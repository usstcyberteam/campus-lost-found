# 代码规范

## 通用
- 标识符用英文；面向用户的文案、接口错误信息用中文；代码注释用中文，只解释"为什么"，不复述代码。
- 一个文件只做一件事。单文件超过 300 行、单函数超过 50 行时拆分。
- 不保留注释掉的代码和未使用的导入、变量。
- 提交信息格式：`类型(范围): 说明`。类型为 feat、fix、refactor、docs、test、chore、style 之一；范围为 backend、frontend、docs、deploy 之一。例：`refactor(backend): 抽出候选匹配服务`。
- 一次提交只包含一个任务的改动。

## 后端（FastAPI + SQLAlchemy 2）

### 分层
| 目录 | 职责 | 禁止 |
|---|---|---|
| `app/api/v1/` | 解析请求、调用依赖做鉴权、调用 service、返回 schema | 写业务判断、直接拼查询 |
| `app/services/` | 业务规则、状态流转、事务 | 依赖 FastAPI 的 Request/Depends |
| `app/models/` | 表结构 | 写业务方法 |
| `app/schemas/` | 请求和响应的 Pydantic 模型 | 访问数据库 |
| `app/core/` | 鉴权、安全、通用依赖 | 写具体业务 |

- service 函数的第一个参数是 `db: Session`，当前用户作为显式参数传入。
- 一次业务操作只 `commit` 一次，由 service 在最后提交。

### 接口
- 路径用复数名词和短横线：`/items/{item_id}/map-anchor`。
- 每个接口都声明 `response_model`，不直接返回手写字典。
- 列表接口统一支持 `limit`（默认 20，最大 100）和 `offset`，返回 `{"items": [...], "total": n, "limit": n, "offset": n}`。
- 出错统一抛 `ApiError(状态码, 代码, 中文信息)`，不直接抛 `HTTPException`。代码取值：`VALIDATION`、`UNAUTH`、`FORBIDDEN`、`NOT_FOUND`、`STATE_CONFLICT`。
- 状态码：参数错 400，未登录 401，无权限 403，不存在 404，状态冲突 409。

### 数据
- 字符串字段必须有长度上限，在 schema 里用 `StringConstraints` 声明。
- 归一化坐标用 `Field(ge=0, le=1)` 约束。
- 外键列和常用筛选列加索引。
- 改表结构必须新增 Alembic 迁移，不依赖 `create_all`。
- 写入前校验被引用的记录存在，不依赖数据库外键报错。

### 类型与风格
- 所有函数写完整类型标注。使用 `X | None`，不用 `Optional`。
- 用 ruff 检查和格式化，行宽 120。

### 测试
- 每个新接口至少三类用例：正常、无权限、非法输入或状态冲突。
- 测试函数命名 `test_场景_预期`，例如 `test_student_cannot_review_claim`。

## 前端（React 18 + TypeScript）

### 目录
| 目录 | 内容 |
|---|---|
| `src/api/` | 每类资源一个文件，导出带类型的请求函数。页面里不直接写接口地址 |
| `src/components/` | 可复用组件，与具体页面无关 |
| `src/pages/` | 页面，一个路由一个文件，只做数据获取和组件拼装 |
| `src/hooks/` | 自定义 Hook |
| `src/styles/` | 设计变量和全局样式 |
| `src/types.ts` | 与后端对应的类型 |

### 写法
- 只用函数组件和 Hooks。组件文件用大驼峰命名，Hook 以 `use` 开头。
- 不使用 `any`。接口返回值必须有类型。
- 不写内联 `style={{...}}`。样式写在与组件同名的 `.module.css` 中，颜色、间距、圆角、字号只引用 `src/styles/tokens.css` 里的 CSS 变量，不写具体数值。
- 请求统一通过 `useAsync` Hook，页面必须处理三种状态：加载中、出错、空数据。
- 提交类按钮在请求期间禁用，防止重复提交。
- 移动端优先：按 375px 宽度设计，可点击元素不小于 44px。
- 表单控件必须有 `label` 或 `aria-label`。
- 用 eslint 和 prettier 检查和格式化。
